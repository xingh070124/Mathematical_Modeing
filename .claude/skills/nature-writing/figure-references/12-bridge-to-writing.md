## 15. Figure 决定 caption 节奏；caption 决定 Results 段落顺序

**Patron principle** — Fig. 1 是读者进入故事的门（SKILL.md §1.3）。

### 15.1 Fig. 1 与 abstract / story shape 的锁链

SKILL.md §1.1 给了 7 种 story shape，§1.3 给了 Fig. 1 四种功能。在 figure 端：

| Story shape | Fig. 1 推荐构图（§1）| 不推荐 |
|---|---|---|
| Bottleneck-broken | 双轴 / before-after（§1.5）| 任务地图 |
| Two-gap synthesis | 模块组装（§1.2） | 时间线 |
| Scale-emergent | 数据流 + scaling curve（§1.1 + 自带 quantitative panel）| 漏斗 |
| Discovery funnel | 漏斗（§1.3） | 模块组装 |
| Human-anchored benchmark | 任务地图 + human bar（§1.4）| 双轴 |
| Trust / audit bridge | 数据流 + audit panel（§1.1 + §1.5 混合）| 漏斗 |
| Limit-redrawn | 任务地图 + boundary panel（§1.4 + capability matrix）| 时间线 |

如果你已经按 SKILL.md §1.1 选定 story shape，Fig. 1 构图基本不能瞎挑。

### 15.2 Caption title 与 Results 子节标题对偶

SKILL.md §5.1 三类 Results 子节标题（method-first / motivation-first / claim-first）应与
对应 figure 的 caption title 风格匹配：

| Results 子节标题 | Caption title |
|---|---|
| method-first (`"Tangram: learning of spatially resolved single-cell transcriptomes by alignment"`) | noun phrase: `"Tangram framework overview"` |
| motivation-first (`"We next tested how Tangram performs when the input scRNA-seq and spatial data are derived from different species"`) | declarative: `"Tangram transfers across species"` |
| claim-first (`"Virchow embeddings yielded the best cancer detection performance on all cancer types"`) | declarative + 重复 claim 的 keyword |

读者从 Results header → call-out → caption title 是连续的 cognitive flow。任一处错位
都会让 reviewer 觉得"reading is bumpy"。

### 15.3 figure 数量与论文骨架

corpus 内 NMI / NC / NCS 的常见配置：

```text
Main figures:        4–8 张（Fig. 1 schematic + 3–7 result figures）
Extended Data:       4–10 张（与 main 风格一致，但 panel 多）
Supplementary:       任意（包含 ablation / 数据细节 / 失败案例）
```

main figure 超过 8 张通常意味着故事不够聚焦——SKILL.md §1.4 "哪些实验进 Supplementary"
也是 figure 端的同一问题。

### 15.4 投稿前三遍扫图

自看：每张图能不能独立读懂？caption 是否 self-contained？
朋友盲看：他能不能复述你的故事？哪张图卡住？
打印 1:1：在投稿尺寸下，最小字号能否读？line 还看得见？三遍都过才送出。
